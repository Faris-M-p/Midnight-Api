Midnight Chronicle — Final Application Architecture
1. Application Concept

Midnight Chronicle is a private family legacy platform.

The main purpose is to allow a family to:

Build and maintain a family tree
Manage family members
Preserve family information
Record family history
Store family stories and memories
Maintain photos and albums
Track important events
Receive family notifications
View family statistics
Provide controlled access through secure family tokens

There is one application, not separate Admin and User applications.

The difference between users is based on their authentication and permissions.

The final principle

The application should stay simple from the user's point of view:

Home → Family → Members → Tree → Stories → Gallery → Timeline → Events

Everything else is supporting functionality.

Notifications stay in the header.
Family identity stays in the header.
Logout stays in the header menu.
Admin does not get a separate dashboard.
Admin only gets Administration → Access Tokens when authorized.
Members and Family Tree remain separate because they serve different purposes.
Add Member stays simple; Edit Member contains the complete information.

This is the structure I would now treat as the final product architecture before moving into individual page UI design.
